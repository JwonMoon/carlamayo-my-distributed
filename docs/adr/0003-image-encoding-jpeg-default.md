# 0003. 이미지는 기본 JPEG(품질 95), 진단용 raw

상태: 채택      날짜: 2026-09-30

## 상황
추론 요청 하나에 4카메라×4프레임(1.5) 또는 7×4(2)의 1920×1080 RGB 이미지가 들어간다.
무압축이면 100 MB / 174 MB다.

## 후보
- raw RGB8 그대로 전송
- JPEG 압축(품질 조절 가능)
- 클라이언트에서 모델 입력 해상도(196,608픽셀 ≈ 512×384)로 미리 축소 후 전송
- PNG(무손실 압축)

## 결정
기본 JPEG 품질 95. `--image-encoding raw`를 진단·parity 검증용으로 남긴다.

## 이유
- 데이터 수집(`data_collect.py:253`)이 이미 JPEG로 저장하고 open-loop는 그것을 읽는다. 즉
  이 프로젝트에서 모델은 처음부터 JPEG 입력으로 평가되어 왔다.
- 모델(1.5)은 입력을 196,608픽셀로 다시 줄인다(`alpamayo_1_5.py:123-124`). 1080p 원본의
  세부와 q95 아티팩트는 대부분 축소 과정에서 사라진다.
- 요청 크기가 100 MB에서 5~8 MB로 줄어 g5/g6e의 네트워크 버스트 한계(최대 10 Gbps) 안에서
  1초 주기를 안정적으로 지킨다.
- 인코딩 비용(1080p 16장 ≈ 0.1~0.3 s)은 `--async`에서 워커 스레드가 부담하므로 tick에 영향이 없다.

## 탈락 이유
- raw 기본: 174 MB는 10 Gbps에서도 0.15~1.4 s라 1초 주기를 넘길 수 있다. 진단용으로만 남긴다.
- 클라이언트 측 축소: 모델 전처리(리사이즈 알고리즘, 종횡비 처리)를 클라이언트가 그대로
  재현해야 하며 버전마다 다르다. 서버가 원본 해상도를 받아 기존 전처리를 그대로 쓰는 편이
  안전하다.
- PNG: 자연 이미지에서 압축률이 낮아(2~3배) 이점이 작고 인코딩이 JPEG보다 느리다.

## 결과
- `module/remote/codec.py`에 `encode_image_stack / decode_image_stack`을 두고 `jpeg`·`raw_rgb8`
  두 인코딩을 지원한다. 서버는 어느 쪽이든 `(cam, frame, H, W, 3) uint8`로 복원한다.
- parity 테스트(로드맵 10단계)에서 raw 대비 JPEG의 궤적 차이를 수치로 기록한다.
