# 0007. 실행마다 결과 폴더를 만들고 run_id를 RPC로 전달해 두 호스트의 폴더명을 맞춘다

상태: 채택      날짜: 2026-09-30

## 상황
업스트림은 영상 파일명이 고정(`module/config.py:23-25`)이라 재실행하면 덮어쓴다. 프로파일링을
추가하면 A(클라이언트)와 B(서버)가 각각 기록을 남기는데, 한 실행의 기록임을 알 수 있도록
두 호스트의 결과가 같은 이름으로 묶여야 한다.

## 후보
- 폴더 이름: (a) 시각 + loop + version + mode + 선택 태그 / (b) 순번(`run_001`) / (c) 사용자가 매번 이름 지정
- 두 호스트 이름 맞추기: (i) 각자 시각으로 이름을 만들고 시계를 맞춰 근접한 것끼리 짝짓기 /
  (ii) B가 이름을 만들어 응답으로 알려줌 / (iii) **A가 이름을 만들어 모든 요청의 메타에 실어 보냄**

## 결정
(a) + (iii). `runs/<YYYYMMDD-HHMMSS>_<loop>_v<version>_<mode>[_<tag>]/`를 A가 만들고 그 이름을
`ClientMeta.run_id`로 보낸다. B는 처음 보는 run_id를 받으면 같은 이름의 폴더를 만든다.

## 이유
- 이름에 시각과 옵션이 들어 있으면 `ls`만으로 무슨 실험인지 알 수 있고 정렬이 시간순이다.
- (iii)은 시계 동기화가 필요 없고 이름이 **정확히** 같다. 요청 메타에 문자열 하나를 더하는
  비용뿐이다. 서버는 여러 클라이언트 실행을 run_id로 구분할 수 있다.
- 실행이 끝난 뒤 `rsync`로 B의 CSV를 A의 같은 폴더에 합치면 한곳에서 분석할 수 있다.

## 탈락 이유
- (b) 순번: 두 호스트에서 순번이 어긋난다. (c) 수동: 잊기 쉽고 중복된다.
- (i) 시계 기반: NTP로도 수백 ms 차이가 날 수 있고 연속 실행 시 짝짓기가 모호하다.
- (ii) B 생성: 클라이언트가 폴더를 만드는 시점이 첫 응답 이후로 밀리고, B 로컬 open-loop처럼
  요청이 없는 경우와 규칙이 달라진다.

## 결과
- 로드맵 1b(`module/run_dir.py`), 4(`ClientMeta.run_id`), 5(서버 폴더 생성), 6b(프로파일링).
- `.gitignore`에 `runs/`.
